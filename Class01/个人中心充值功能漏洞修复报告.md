## 6. 漏洞修复及修复后测试

### BL-001：负值充值漏洞修复

#### 修复前问题

`/recharge` 路由直接使用 `balance = balance + amount` 更新余额，**未检查 `amount` 是否为正数**。攻击者可提交负值金额实现"扣款"操作。

#### 修复代码（`app.py`）

```python
# 修复 BL-001：金额必须大于0
if amount <= 0:
    return redirect(f"/profile?user_id={user_id}&error=金额必须大于0")
```

#### 修复验证

| 操作 | 请求 | 修复前 | 修复后 |
|:-----|:-----|:------:|:------:|
| 充值 -50 | `user_id=3, amount=-50` | ✅ 余额-50（扣款成功） | ❌ 拦截提示"金额必须大于0" |
| 充值 -99999 | `user_id=1, amount=-99999` | ✅ 清空管理员余额 | ❌ 拦截 |

**测试结果**：
```
userA 充负值 -50
→ Location 解码: /profile?user_id=3&error=金额必须大于0
→ 结果: ✅ 已拦截
```

### BL-002：浮点数精度漏洞修复

#### 修复前问题

金额使用 `float` 类型存储和计算。浮点数无法精确表示 `0.01` 等十进制小数，多次累加后产生精度误差（如 `0.03` 变成 `0.02999999998`）。

#### 修复代码（`app.py`）

```python
from decimal import Decimal

# 修复 BL-002：使用 Decimal 替代 float 避免精度问题
amount = Decimal(str(amount_str))     # 将字符串直接转为 Decimal
current_balance = Decimal(str(get_current_user_balance(user_id)))
new_balance = current_balance + amount
update_balance_in_db(user_id, float(new_balance))  # 存储时转回 float
```

#### 修复验证

| 操作 | 修复前（float） | 修复后（Decimal） |
|:-----|:----------------|:------------------|
| 充值 0.01 × 3 次 | `0.029999999999999999` ❌ | `0.03` ✅ |

**测试结果**：
```
充 0.01 三次后余额: 100.03 ✅ 无精度问题
（修复前为: 100.02999999998 ❌）
```

> （在此处插入 Decimal 修复后精度正常的余额截图——显示精确的 100.03 而非 100.02999999998）

### BL-003：无频率限制漏洞修复

#### 修复前问题

`/recharge` 接口无任何频率限制，攻击者可在 **0.11 秒内提交 10 次充值请求**。

#### 修复代码（`app.py`）

```python
# 修复 BL-003：频率限制 - 每分钟最多充5次
now = time.time()
last_time = session.get("last_recharge_time", 0)
recharge_count = session.get("recharge_count", 0)

if now - last_time > 60:
    # 新的一分钟，重置计数
    session["recharge_count"] = 1
    session["last_recharge_time"] = now
elif recharge_count >= 5:
    return redirect(f"/profile?user_id={user_id}&error=充值过于频繁，请稍后再试")
else:
    session["recharge_count"] = recharge_count + 1
```

#### 修复验证

| 操作 | 修复前 | 修复后 |
|:-----|:------:|:------:|
| 连续充值 6 次 | ✅ 全部成功（0.11秒完成） | ❌ 第 6 次被拦截 |
| 1 分钟可发起次数 | ~5454 次 | 最多 5 次 |

**测试结果**：
```
连续充值 5 次（正常）→ 前5次成功
第 6 次充值 → Location 解码: /profile?user_id=3&error=充值过于频繁，请稍后再试
→ 结果: ✅ 已拦截
```

### IDOR-001：任意用户资料查看漏洞修复

#### 修复前问题

`/profile` 路由**无 `@login_required`**，且**不校验 `user_id` 是否与当前登录用户匹配**。任何用户（包括未登录）可通过修改 URL 参数查看任意用户资料。

#### 修复代码（`app.py`）

```python
# 修复 IDOR-001：添加登录保护和权限校验
@app.route("/profile")
@login_required
def profile():
    current_user_id = session.get("user_id")
    target_user_id = request.args.get("user_id")
    
    ...
    # 权限校验：只能查看自己的个人中心
    if str(target_user_id) != str(current_user_id):
        return render_template("profile.html", user=None, 
                               error="无权查看其他用户的资料", user_id=None)
```

#### 修复验证

| 操作 | 修复前 | 修复后 |
|:-----|:------:|:------:|
| userA 查看 admin(id=1) | ✅ 成功查看管理员资料 | ❌ 提示"无权查看其他用户的资料" |
| userA 查看 userB(id=4) | ✅ 成功查看陌生人资料 | ❌ 提示"无权查看其他用户的资料" |
| userA 查看自己(id=3) | ✅ 正常显示 | ✅ 正常显示 |
| 未登录直接访问 | ✅ 可查看任意用户 | ❌ 跳转登录页 |
| 遍历 user_id=1~100 | ✅ 枚举所有用户 | ❌ 只能看自己 |

**测试结果**：
```
userA 查看 admin(id=1) 资料 → 提示"无权查看其他用户的资料" ✅ 已拦截
userA 查看 userB(id=4) 资料 → 提示"无权查看其他用户的资料" ✅ 已拦截
userA 查看自己(id=3) 资料   → 正常显示 userA@test.com ✅ 正常
```

### IDOR-002：越权充值漏洞修复

#### 修复前问题

`/recharge` 路由的 `user_id` 直接来自表单参数，**无任何权限校验**。攻击者可通过修改隐藏字段或直接 POST 给任意用户充值/扣款。

#### 修复代码（`app.py`）

```python
# 修复 IDOR-002：只能给自己充值
if user_id != current_user_id:
    return redirect("/profile?error=无权操作其他用户账户")
```

#### 修复验证

| 操作 | 修复前 | 修复后 |
|:-----|:------:|:------:|
| userA 给 admin 充值 100 | ✅ 成功 | ❌ 提示"无权操作其他用户账户" |
| userA 给 userB 充值 500 | ✅ 成功 | ❌ 提示"无权操作其他用户账户" |
| userA 给 admin 充 -99999 | ✅ 清空管理员余额 | ❌ 拦截（越权+负值双重拦截） |
| userA 给自己充值 | ✅ 正常 | ✅ 正常 |

**测试结果**：
```

```
