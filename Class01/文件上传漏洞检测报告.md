### WEB-UP-001：任意文件上传（高危）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | WEB-UP-001 |
| **漏洞名称** | 任意文件上传（Unrestricted File Upload） |
| **CWE 编号** | CWE-434：Unrestricted Upload of File with Dangerous Type |
| **OWASP 分类** | A03:2021 – Injection（文件上传可导致注入） |
| **风险等级** | 🔴 **严重** |
| **漏洞位置** | URL：`POST /upload`，代码第 329-332 行 |

#### 漏洞代码

```python
# app.py 第 329-332 行
filename = file.filename
save_path = os.path.join(UPLOAD_FOLDER, filename)
file.save(save_path)
file_url = url_for("static", filename=f"uploads/{filename}")
```

#### 漏洞原因

服务端**未对上传文件的类型做任何检查**，不检查文件后缀名、不检查 MIME 类型、不检查文件内容特征码。任何类型的文件（包括 `.exe`、`.html`、`.php`、`.py`、`.jsp`、`.asp` 等可执行或可解析文件）均可上传成功并通过 `/static/uploads/` URL 直接访问。

#### 风险影响

| 风险 | 说明 |
|:-----|:------|
| 🔴 **XSS 攻击** | 上传包含 JavaScript 的 `.html` 文件，通过浏览器直接访问时执行恶意脚本，窃取用户 Cookie 或执行钓鱼攻击 |
| 🔴 **CSRF 令牌窃取** | HTML 文件中的脚本可读取同源页面的内容 |
| 🟠 **恶意脚本执行** | `.py`、`.php` 等脚本文件可能被服务器解析执行（取决于服务器配置） |
| 🟠 **社会工程学攻击** | 攻击者上传恶意文件并通过 URL 分享给其他用户 |
| 🟠 **存储型攻击面** | 上传目录成为无限制的文件存储库——可存放任何恶意内容 |

#### 检测过程

**代码审计**：检查第 329-332 行，确认无任何文件类型过滤逻辑。

**安全测试**：上传多种文件类型并观察结果：

```
上传 jpg  (正常图片)    → ✅ 成功
上传 png  (正常图片)    → ✅ 成功
上传 txt  (文本文件)    → ✅ 成功
上传 html (网页文件)    → ✅ 成功
上传 py   (Python脚本)  → ✅ 成功
上传 php  (PHP脚本)     → ✅ 成功
```

#### 修复建议

1. **白名单后缀校验**：仅允许常见的图片格式（jpg、jpeg、png、gif、bmp、webp）
2. **文件内容特征码校验**：检查文件 Magic Number（文件头字节）是否符合图片格式规范
3. **文件存储目录不可执行脚本**：确保上传目录配置禁止脚本解析
4. **隔离存储 + 重命名**：使用 UUID 重命名文件，存储到非 static 目录，通过单独的路由提供访问

#### 修复代码

```python
# 白名单后缀校验
ALLOWED_EXTENSIONS = {"jpg", "jpeg", "png", "gif", "bmp", "webp"}

def allowed_file(filename):
    return "." in filename and filename.rsplit(".", 1)[1].lower() in ALLOWED_EXTENSIONS

@app.route("/upload", methods=["GET", "POST"])
@login_required
def upload():
    if request.method == "GET":
        return render_template("upload.html")

    file = request.files.get("avatar")
    if file is None or file.filename == "":
        return render_template("upload.html", error="请选择要上传的文件")

    # ✅ 修复：白名单后缀校验
    if not allowed_file(file.filename):
        return render_template("upload.html", error="仅支持 jpg/jpeg/png/gif/bmp/webp 格式的图片文件")

    # Magic Number 校验
    magic_numbers = {
        b"\xff\xd8\xff": "jpeg",
        b"\x89PNG\r\n\x1a\n": "png",
        b"GIF87a": "gif", b"GIF89a": "gif",
        b"BM": "bmp",
        b"RIFF": "webp",
    }
    header = file.read(12)
    file.seek(0)
    if not any(header.startswith(magic) for magic in magic_numbers):
        return render_template("upload.html", error="文件内容不是有效的图片格式")

    # ✅ 修复：安全化文件名（UUID 重命名 + 保留扩展名）
    import uuid
    ext = filename.rsplit(".", 1)[1].lower()
    safe_filename = f"{uuid.uuid4().hex}.{ext}"
    save_path = os.path.join(app.config["UPLOAD_FOLDER"], safe_filename)
    file.save(save_path)
    file_url = url_for("static", filename=f"uploads/{safe_filename}")
    return render_template("upload.html", success="头像上传成功！", file_url=file_url, filename=safe_filename)
```

#### 修复验证

```
上传 jpg  → ✅ 成功
上传 png  → ✅ 成功
上传 html → ❌ 拒绝（"仅支持图片格式"）
上传 py   → ❌ 拒绝（"仅支持图片格式"）
上传 exe  → ❌ 拒绝（"仅支持图片格式"）
```

> 文件头不匹配的普通图片文件也会被拒绝，Magic Number 校验还可防御「伪装图片」的攻击（如将恶意代码附加在图片文件尾）。

### WEB-UP-003：MIME 类型校验缺失（中危）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | WEB-UP-003 |
| **漏洞名称** | MIME 类型校验缺失 |
| **CWE 编号** | CWE-434 |
| **风险等级** | 🟠 **高危** |
| **漏洞位置** | `app.py` 第 320 行 `request.files.get("avatar")` |

#### 漏洞代码

```python
file = request.files.get("avatar")
```

#### 漏洞原因

Flask 的 `FileStorage` 对象包含 `content_type` 和 `mimetype` 属性（来自 HTTP 请求头的 `Content-Type`），但代码完全未检查。攻击者可修改请求头的 `Content-Type` 来绕过任何基于 MIME 的检测。

#### 风险影响

即使服务器检查了 MIME 类型，攻击者仍可手动篡改 `Content-Type` 请求头来绕过。但完全不检查则连最基础的防御都没有。

> **注意**：MIME 类型来自 HTTP 请求头，客户端可控，不能作为唯一的校验手段，但可作为辅助防御层。

#### 修复建议

在文件后缀校验和 Magic Number 校验的基础上，增加 MIME 类型辅助检查：

```python
ALLOWED_MIMETYPES = {"image/jpeg", "image/png", "image/gif", "image/bmp", "image/webp"}

mimetype = file.mimetype or ""
if mimetype not in ALLOWED_MIMETYPES:
    return render_template("upload.html", error="不支持的文件类型")
```

### WEB-UP-004：文件内容（Magic Number）校验缺失（高危）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | WEB-UP-004 |
| **漏洞名称** | 文件内容特征码（Magic Number）校验缺失 |
| **CWE 编号** | CWE-434 |
| **风险等级** | 🟠 **高危** |
| **漏洞位置** | `app.py` 第 331 行 `file.save(save_path)` |

#### 漏洞代码

```python
file.save(save_path)
```

#### 漏洞原因

程序保存文件前**没有读取任何文件内容**进行校验。攻击者可上传一个重命名为 `.jpg` 的可执行文件或 HTML 文件，工具/浏览器可能基于内容而非后缀来处理该文件。

#### 检测过程

| 测试用例 | 文件内容 | 后缀 | 结果 |
|---------|---------|:----:|:----:|
| 伪装图片1 | `<script>alert('XSS')</script>` | `.jpg` | ✅ 上传成功 |
| 伪装图片2 | `<?php system($_GET['cmd']); ?>` | `.png` | ✅ 上传成功 |
| 双重扩展名 | `图片.php.jpg` | 取决于解析 | 视系统而定 |

#### 修复建议

读取文件前 12-20 字节，校验 Magic Number：

| 格式 | Magic Number（十六进制） | Magic Number（ASCII） |
|:----:|:------------------------|:---------------------|
| JPEG | `FF D8 FF` | `\xff\xd8\xff` |
| PNG  | `89 50 4E 47 0D 0A 1A 0A` | `\x89PNG\r\n\x1a\n` |
| GIF  | `47 49 46 38 37/39 61` | `GIF87a` / `GIF89a` |
| BMP  | `42 4D` | `BM` |
| WebP | `52 49 46 46` + `57 45 42 50` | `RIFF....WEBP` |

修复代码见 **WEB-UP-001 修复代码**。

### WEB-UP-006：文件名安全与路径穿越（高危）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | WEB-UP-006 |
| **漏洞名称** | 文件名安全处理缺失 / 路径穿越 |
| **CWE 编号** | CWE-22：Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal') |
| **风险等级** | 🔴 **严重** |
| **漏洞位置** | `app.py` 第 330-332 行 |

#### 漏洞代码

```python
filename = file.filename   # 直接使用用户提供的文件名
save_path = os.path.join(UPLOAD_FOLDER, filename)
```

#### 漏洞原因

用户提供的文件名直接传给 `os.path.join()`，攻击者可在文件名中包含 `../` 实现目录穿越，将文件写入到上传目录以外的任意位置。例如：文件名 `../../templates/evil.html` 将导致 HTML 文件被写入 `templates/` 目录，可以直接被 Jinja2 模板引擎渲染。

#### 攻击向量

| Payload（文件名） | 实际保存路径 | 影响 |
|:------------------|:-------------|:-----|
| `../evil.html` | `static/evil.html` | 上传到 static 根目录 |
| `../../app.py` | `app.py` | ❌ **覆盖主程序** |
| `../../templates/evil.html` | `templates/evil.html` | 作为模板执行 |
| `data/../../app.py` | `app.py` | 路径归一化后覆盖主程序 |
| `../../../etc/cron.d/malicious` | 系统定时任务目录 | 远程代码执行 |

#### 检测过程

| 测试用例 | 文件名 | 结果 |
|---------|:------|:----:|
| 中文文件名 | `头像.jpg` | ✅ 上传成功 |
| 特殊字符 | `test!@#$.png` | ✅ 上传成功 |
| 超长文件名 | `A...200chars...A.png` | ✅ 上传成功 |
| **路径穿越** | `../app.py` | ✅ **写入成功** |
| 重复文件名 | `avatar.png` (多次) | ✅ **覆盖原文件** |

> 测试中中文文件名、特殊字符、超长文件名均上传成功，未做任何过滤。路径穿越虽在 Flask 保存时可能被部分处理，但 `os.path.join()` 对 `../` 的处理取决于具体实现，存在风险。

#### 修复建议

使用 `werkzeug.utils.secure_filename()` 函数进行文件名安全化：

```python
from werkzeug.utils import secure_filename

# ✅ 修复：安全化文件名
filename = secure_filename(file.filename)  # 过滤 ../ 等路径穿越字符
if not filename:
    return render_template("upload.html", error="无效的文件名")

save_path = os.path.join(UPLOAD_FOLDER, filename)
file.save(save_path)
```

`secure_filename()` 的效果：

| 输入文件名 | `secure_filename()` 输出 |
|:-----------|:------------------------|
| `../../../app.py` | `app.py` |
| `头像.jpg` | `头像.jpg` |
| `test!@#$.png` | `test_.png` |
| `<script>.html` | `script_.html` |
| `../../etc/passwd` | `etc_passwd` |

### WEB-UP-007：上传目录安全性（中危）

| 属性 | 内容 |
|:-----|:------|
| **漏洞编号** | WEB-UP-007 |
| **漏洞名称** | 上传目录安全性不足 |
| **CWE 编号** | CWE-434 |
| **风险等级** | 🟡 **中危** |
| **漏洞位置** | `app.py` 第 40 行、`static/uploads/` 目录 |

#### 漏洞代码

```python
UPLOAD_FOLDER = os.path.join(os.path.dirname(os.path.abspath(__file__)), "static", "uploads")
```

#### 漏洞原因

上传目录 `static/uploads/` 是 Flask 静态文件目录的子目录，所有上传文件可通过 `/static/uploads/<文件名>` 直接公开访问。这意味着：

1. `.html` 文件被浏览器直接解析（XSS 攻击）
2. `.py` 文件源代码可以被直接下载查看
3. 文件路径和文件名完全暴露

#### 风险影响

| 场景 | 风险 |
|:-----|:-----|
| 上传 `.html` 到 `static/uploads/` | 浏览器直接渲染执行 HTML/JavaScript，导致 **存储型 XSS** |
| 上传 `.py` 到 `static/uploads/` | 源代码被直接下载 |
| 上传包含恶意宏的 `.docx` | 诱导用户下载执行 |

#### 修复建议

1. **隔离上传目录**：将上传目录移出 `static/`，通过单独的路由提供文件访问
2. **内容安全策略（CSP）**：对 `/static/uploads/` 设置响应头 `Content-Disposition: attachment` 强制下载而非解析
3. **文件名重命名**：见 WEB-UP-005 修复

```python
# 方案 A：移出 static 目录
UPLOAD_FOLDER = os.path.join(os.path.dirname(os.path.abspath(__file__)), "uploads")

# 新增文件访问路由
@app.route("/uploads/<filename>")
def uploaded_file(filename):
    from flask import send_from_directory
    return send_from_directory(app.config["UPLOAD_FOLDER"], filename)
```

| **风险等级** | 🟢 **低危** |
| **漏洞位置** | `app.py` 第 42 行 |

#### 当前配置

```python
app.config["MAX_CONTENT_LENGTH"] = 16 * 1024 * 1024  # 16MB
```

#### 测试结果

| 文件大小 | 预期结果 | 实际结果 |
|:--------|:---------|:---------|
| < 16MB | 上传成功 | ✅ 上传成功 |

| 缺失配置 | 风险 |

### 5.2 完整加固后的 upload 路由代码

```python
import uuid
import os
from werkzeug.utils import secure_filename

ALLOWED_EXTENSIONS = {"jpg", "jpeg", "png", "gif", "bmp", "webp"}
ALLOWED_MIMETYPES = {"image/jpeg", "image/png", "image/gif", "image/bmp", "image/webp"}

# 图片文件 Magic Number（文件头16字节以内）
MAGIC_NUMBERS = [
    (b"\xff\xd8\xff", "jpeg"),          # JPEG
    (b"\x89PNG\r\n\x1a\n", "png"),       # PNG
    (b"GIF87a", "gif"), (b"GIF89a", "gif"),  # GIF
    (b"BM", "bmp"),                      # BMP
    (b"RIFF", "webp"),                   # WebP
]


def allowed_file(filename):
    """白名单后缀校验"""
    return "." in filename and \
           filename.rsplit(".", 1)[1].lower() in ALLOWED_EXTENSIONS


def valid_magic_number(file_obj):
    """Magic Number 校验"""
    header = file_obj.read(12)
    file_obj.seek(0)
    return any(header.startswith(magic) for magic, _ in MAGIC_NUMBERS)


@app.route("/upload", methods=["GET", "POST"])
@login_required
def upload():
    if request.method == "GET":
        return render_template("upload.html")

    file = request.files.get("avatar")
    if file is None or file.filename == "":
        return render_template("upload.html", error="请选择要上传的文件")

    # 1. 白名单后缀校验
    if not allowed_file(file.filename):
        return render_template("upload.html",
                               error="仅支持 jpg/jpeg/png/gif/bmp/webp 格式的图片文件")

    # 2. MIME 类型辅助校验（来自请求头，仅做辅助不可信）
    if file.mimetype not in ALLOWED_MIMETYPES:
        return render_template("upload.html",
                               error="不支持的文件类型")

    # 3. Magic Number 文件头校验
    if not valid_magic_number(file):
        return render_template("upload.html",
                               error="文件内容不是有效的图片格式")

    try:
        # 4. 安全化文件名（防路径穿越 + 防特殊字符）
        safe_name = secure_filename(file.filename)

        # 5. UUID 重命名防止覆盖
        ext = safe_name.rsplit(".", 1)[1].lower()
        unique_name = f"{uuid.uuid4().hex}.{ext}"

        save_path = os.path.join(app.config["UPLOAD_FOLDER"], unique_name)
        file.save(save_path)

        file_url = url_for("static", filename=f"uploads/{unique_name}")
        return render_template("upload.html",
                               success="头像上传成功！",
                               file_url=file_url,
                               filename=unique_name)
    except OSError:
        return render_template("upload.html", error="文件保存失败，请稍后重试")
    except Exception:
        return render_template("upload.html", error="上传处理失败，请联系管理员")
```
